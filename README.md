# SYMBA v5 — Lie-Symmetry Benchmark on Burgers: KAN Operators vs FNO

One periodic viscous Burgers benchmark (`u_t + u u_x = nu u_xx`, nu = 0.02, N=1000, S=512,
20 future frames) that trains every model under an identical budget and asks one question:

> **does an exact Lie symmetry (the Galilean boost) and/or the exact Hopf–Cole solution
> structure make the learning problem easier — and by how much?**

Headline results (mean relative-L2 on the held-out test split, lower is better):

| model | symmetry | rel-L2 | vs FNO-raw | params | inference ms/batch | s/epoch |
|---|---|---|---|---|---|---|
| FNO (reference) | none | 0.0092 | — | 109,428 | ~1.3 | ~0.15 |
| ModalKAN | none | 0.0485 | −425% | 234,240 | ~1.2 | ~0.14 |
| ChebyKAN | none | 0.0357 | −287% | 63,220 | ~4 | ~0.4 |
| KANO-R | none | 0.0178 | −93% | 236,052 | ~32 | ~2.0 |
| **CH-KAN (winner)** | none | **<5e-5** | **+99.8%** | **22** | ~54 | ~2.6 |
| FNO | Galilean closed-form | 0.0010 | +89.7% | 109,428 | ~1.3 | ~0.15 |
| KANO-R | Galilean closed-form | 0.0023 | +75.4% | 236,052 | ~32 | ~2.0 |
| **CH-KAN** | Galilean closed-form | **<5e-5** | **+99.8%** | **22** | ~54 | ~2.6 |

The winner **CH-KAN** is the exact Hopf–Cole/Wiener solution operator of Burgers evaluated in
log space (cancellation-free `logsumexp` softmax), with two tiny learned rational correction
kernels. At initialization it *is* the analytical solution (untrained error 2.3e-05); training
only learns the data-vs-ideal-physics residual — and every learned kernel is a drawable curve.

## Launching

### Option A — Colab / Jupyter (recommended)
1. Open `SYMBa_Burgers_Lie_Symmetry_Enhanced_v4.ipynb` (Colab: Runtime → Change runtime type → **GPU T4**).
2. `CONFIG["quick_test"]` is `True` by default → runs end-to-end in ~2 min with a small subset
   (N=120, 3 epochs). Numbers are meaningless at this setting; it only proves the pipeline.
3. For the real benchmark set `CONFIG["quick_test"] = False` in the config cell and Run all
   (~12–15 min on a T4-class GPU, of which ~50 s is data generation).

### Option B — local scripted runners
Requires Python ≥3.10 with `torch`, `numpy`, `matplotlib` (no other dependencies).

```bash
python _run_v5_script.py     # quick-test (small, fast, sanity only)
python _run_v5_full.py       # FULL budget: N=1000, 100 epochs — the published numbers
```

### Option C — regenerate the notebook from source
After editing model/architecture code in `_build_v5.py`:

```bash
python _build_v5.py          # rewrites SYMBa_Burgers_Lie_Symmetry_Enhanced_v4.ipynb (in place!)
```

If you prefer the runners over the notebook, regenerate them after any notebook change with:

## Editing models & parameter counts (CONFIG cell)

Everything lives in the `CONFIG` dict of the first code cell (and identically in
`_build_v5.py`). Knobs, and what they change:

| key | controls | effect on param count |
|---|---|---|
| `fno_width`, `fno_modes`, `fno_layers` | FNO reference size | ~109k at defaults; scale width for bigger |
| `kan_hidden` | hidden width of ModalKAN trunk + pointwise KANs | dominant cost of ModalKAN (2.14× FNO at 128) |
| `modal_M` | Fourier modes retained by ModalKAN | head size = `2·M·T`; raise for sharper spectra |
| `modal_sub_stride` | u0 subsample stride fed to ModalKAN (shock position info) | adds `S/stride` input features |
| `cheby_degree` | degree D of Chebyshev kernels (T₀..T_D) | ChebyKAN mixers scale ×(D+1) |
| `rat_p`, `rat_q` | numerator/denominator degrees of ALL rational kernels | (p+1)+(q+1) coefficients per kernel unit |
| `kano_width`, `kano_layers` | KANO-R inner width / depth | width² per mixing layer ×2 (base + KAN) |
| `epochs`, `batch_size`, `lr` | shared training budget (fairness contract — same for every model) | — |
| `seed`, `S`, `N`, `T`, `n_test`, `n_val` | data + split (one shared permutation for every model) | — |
| `quick_test` | shrink to N=120/3 epochs smoke run | — |

### Swap or add a model
`MODEL_KINDS = ["FNO", "ModalKAN", "ChebyKAN", "KANO-R", "CH-KAN"]` — comment entries out to
skip training them. To add your own operator:

1. Implement a class taking `(B, S, in_ch)` → `(B, T_out, S)` (see any existing one).
2. Register it in `make_model(kind, T_out, S)` and `MODEL_KINDS`.
3. (Optional) give it a branch in the kernel-visualization cell so its kernels get plotted.

### Add a symmetry arm
`GAL_ARMS = ["FNO", "KANO-R"] + ([winner] if winner not in ("FNO", "KANO-R") else [])` in the
Galilean-arms cell — add any `MODEL_KINDS` entry; the exact v4 canonicalization/inversion is
architecture-agnostic.

### Switch kernel families
`make_kernel(name, n_units)` supports `"rational"`, `"chebyshev"`, `"bspline"`. Pass
`kernel=...` to any `KANPointwise1d`.

## The leakage contract (do not break)

Every eval-time symmetry parameter derives from **u0 only**:

- Galilean drift `U = mean(u0)` is an exact conserved invariant (verified dataset-wide to 3.6e-07);
- the inversion context carries **only** `{'Ubar'}` — the v4-era `means_future` is gone;
- one shared permutation (seed 0) partitions train/val/test with zero overlap;
- no dataset-wide normalization statistics exist;
- KANO-R/CH-KAN selection uses **validation error only**.

The audit cell asserts all of this at run time. Independently (out-of-band probes): randomizing
every future frame of the test set leaves CH-KAN predictions and all Galilean displacements
bit-identical — no future-frame information can enter the pipeline.

## Honest caveats

- CH-KAN embeds the closed-form solution structure using the known ν (same fairness status as
  the closed-form Galilean drift). It is a physics-structured operator with 22 learned correction
  parameters, not a from-scratch learner — the generic-KAN rows exist precisely to show that
  distinction.
- Speed: FNO is ~40× faster at inference than CH-KAN (its softmax kernel is O(T·S²)). For
  throughput-bound deployment use FNO+Gal-cf (0.0010 at ~1.3 ms/batch); for solver-grade
  accuracy use CH-KAN.
- The generic KANs losing to FNO raw is itself a result: architecture choice must follow the
  PDE structure, not just function-class flexibility.
